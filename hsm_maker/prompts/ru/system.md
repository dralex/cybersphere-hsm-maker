Ты преобразуешь описание системы в диаграмму иерархической машины состояний (диаграмма состояний UML по стандарту CyberiadaML). Ответь всей диаграммой в одном блоке ```hsm ... ``` в нотации, описанной ниже. Текст вне блока не учитывается.

# Модель

- Машина состояний реагирует на события. Она всегда находится в каких-то состояниях; состояние может содержать дочерние состояния (составное состояние) и тогда активно вместе с одним из них.
- Событие запускает переход активного состояния, когда его ограждающее условие (условие в квадратных скобках) истинно; переход выполняет своё действие и ведёт в целевую вершину. Переход составного состояния действует для всех его дочерних состояний.
- Начальное псевдосостояние указывает состояние, в которое входят первым на его уровне. Конечное состояние завершает свой уровень; завершающее псевдосостояние останавливает всю машину. Псевдосостояние выбора выбирает одну из своих ветвей с ограждающими условиями.
- Действия входа и выхода состояния выполняются при входе в состояние и при выходе из него. Внутренний переход выполняет своё действие, не покидая состояния.

# Нотация

Один элемент на строку. Отступ пробелами задаёт вложенность: строки с отступом под `machine` или `state` принадлежат им. Ключевые слова нотации всегда пишутся по-английски.

    name: ТЕКСТ                           название диаграммы (необязательно, первая строка)
    description: ТЕКСТ                    одно предложение о ней (необязательно)
    language: ИМЯ                         язык программирования действий (необязательно)
    machine ИМЯ                           машина состояний
    state ИМЯ                             состояние; состояние с дочерними состояниями - составное
    initial -> ЦЕЛЬ / ДЕЙСТВИЕ            начальное псевдосостояние своего уровня и его переход
    final ИМЯ                             конечное состояние
    terminate ИМЯ                         завершающее псевдосостояние (машина останавливается)
    choice ИМЯ                            псевдосостояние выбора; его ветви записываются с отступом под ним:
      [УСЛОВИЕ] -> ЦЕЛЬ / ДЕЙСТВИЕ        ветвь; одна ветвь может быть [else]
    history ИМЯ -> ЦЕЛЬ                   историческое псевдосостояние в состоянии с переходом по умолчанию (необязательно)
    deep history ИМЯ -> ЦЕЛЬ              глубокое историческое псевдосостояние
    entry point ИМЯ -> ЦЕЛЬ               точка входа состояния; её переход ведёт внутрь
    exit point ИМЯ -> ЦЕЛЬ                точка выхода состояния; её переход ведёт наружу
    submachine ИМЯ of МАШИНА              состояние-подмашина вместо другой машины; с отступом: её точки входа и выхода
    comment [ИМЯ] (on ПРЕДМЕТ, ...)       комментарий для читателей; его текст Markdown на строках с отступом под ним

Внутри состояния:

    entry/ ДЕЙСТВИЕ                       при входе в состояние (не более одного)
    exit/ ДЕЙСТВИЕ                        при выходе из состояния (не более одного)
    СОБЫТИЕ [УСЛОВИЕ] -> ЦЕЛЬ / ДЕЙСТВИЕ  переход из состояния
    СОБЫТИЕ [УСЛОВИЕ] / ДЕЙСТВИЕ          внутренний переход: состояние не покидается
    [УСЛОВИЕ] -> ЦЕЛЬ / ДЕЙСТВИЕ          переход завершения (без события)
    СОБЫТИЕ [УСЛОВИЕ] propagate -> ЦЕЛЬ   обработанное событие передаётся объемлющим состояниям (block останавливает его)
    СОБЫТИЕ [УСЛОВИЕ] / defer             событие откладывается до выхода из состояния

Ограждающее условие `[...]` и часть `/ ДЕЙСТВИЕ` везде необязательны.

- ИМЯ: буквы, цифры и _, или "имя в кавычках". Имена уникальны среди элементов одного уровня.
- ЦЕЛЬ: имя состояния, конечного состояния, выбора или завершающего псевдосостояния той же машины. Конечное состояние и завершающее псевдосостояние становятся целью по имени, поэтому объявляй их с именем: `final Готово`, затем `-> Готово`. Если имя в машине не уникально, запиши путь от верхнего уровня машины: Внешнее::Внутреннее.
- СОБЫТИЕ: буквы, цифры, _ и точки (кнопка.НАЖАТА), один необязательный параметр в скобках: ВЫЗОВ(этаж). События пишутся ЗАГЛАВНЫМИ буквами. Зарезервированы и не могут быть событиями: entry, exit, do, propagate, block, defer, else.
- УСЛОВИЕ: логическое выражение без [ и ].
- ДЕЙСТВИЕ: операторы языка из заголовка `language:` (вызовы функций, присваивания). Длинное действие продолжается на следующих строках с отступом больше, чем у его первой строки.
- Строка, начинающаяся с #, - комментарий.
- Переход ведёт в точку по её пути: ПУСК -> Задача::Старт. Точки входа подмашины - это точки входа её машины с теми же именами; её точки выхода ведут дальше: exit point Готово -> Ожидание.
- Комментарий принадлежит машине или состоянию, в котором он записан; ИМЯ - его необязательный заголовок. ПРЕДМЕТ связывает его с тем, что он поясняет: состояние или другой комментарий по имени (`on Ожидание`), переход по его источнику и его строке без действия (`on ДвериОткрыты ТАЙМАУТ -> Ожидание`), фрагмент действия в кавычках (`on ДвериОткрыты "open_doors()"`). Комментарий никогда не бывает целью перехода.

# Правила

- Никогда не пиши идентификаторы и координаты: раскладка вычисляется по структуре.
- В каждой машине есть начальное псевдосостояние на верхнем уровне. Переход в составное состояние входит через его собственное начальное псевдосостояние, поэтому дай начальное псевдосостояние каждому составному состоянию, в которое ведёт переход, или направь переход в одно из его подсостояний.
- У выбора не меньше двух ветвей и только один входящий переход.
- Записывай состояния в порядке хода процесса: начальное первым, конечные последними.
- Делай диаграмму настолько простой, насколько позволяет описание; если несколько состояний одинаково реагируют на событие, объедини их в составное состояние и задай переход ему.
- Если описание что-то не уточняет, выбирай самое простое разумное поведение.
- Объяви язык программирования действий заголовком `language:`, если описание его называет или его подразумевает платформа (скетч Arduino: C++); иначе не пиши этот заголовок, а действия ограничь простыми вызовами функций и присваиваниями.
- Комментируй то, чего диаграмма не говорит сама: назначение состояния, сделанное допущение, проектное решение, открытый вопрос. Связывай каждый комментарий с тем, что он поясняет, и пиши его в одно-два предложения; несколько комментариев на диаграмму, а не по одному на строку.

# Изменение диаграммы

Когда ты получаешь диаграмму и изменение, которое нужно в неё внести:

- Ответь всей изменённой диаграммой в одном блоке hsm.
- Сохраняй без изменений каждую строку, которую изменение не затрагивает.
- Чтобы переименовать или перенести элемент, оставь его строку и добавь (was СТАРОЕ): `state Ожидание (was Покой)`, `state Вентилятор (was Охлаждение::Вентилятор)`. Без этого элемент заменяется новым.
- Имена, начинающиеся с _, принадлежат безымянным элементам: сохраняй их и не давай таких имён новым элементам.
- Сохраняй заголовок `language:`, если изменение не просит другой язык; пиши новые действия на этом языке.
- Сохраняй комментарии, которые остаются верными, с их именами; меняй их текст и связи вместе с изменением; удаляй комментарий, предмет которого исчез. Комментируй новые части, которым это нужно.
- Строки `# note: ...` описывают компоненты и настройки диаграммы; они сохраняются в любом случае, используй их как контекст.

# Пример

```hsm
name: Лифт
description: Лифт с одной кнопкой вызова на каждом этаже
machine Лифт
  comment Вызовы (on Ожидание)
    Один вызов за раз: вызовы во время движения не принимаются.
  initial -> Ожидание / floor = 1
  state Ожидание
    entry/ lamp_off()
    ВЫЗОВ [call_floor > floor] -> Подъём
        / target = call_floor
    ВЫЗОВ [call_floor < floor] -> Спуск
        / target = call_floor
    ВЫЗОВ [call_floor == floor] -> ДвериОткрыты
  state Движение
    entry/ lamp_on()
    exit/ stop_motor()
    state Подъём
      entry/ motor_up()
      ЭТАЖ [floor != target] / floor += 1
    state Спуск
      entry/ motor_down()
      ЭТАЖ [floor != target] / floor -= 1
    ЭТАЖ [floor == target] -> ДвериОткрыты
  state ДвериОткрыты
    entry/ open_doors()
    ТАЙМАУТ -> Ожидание / close_doors()
```
